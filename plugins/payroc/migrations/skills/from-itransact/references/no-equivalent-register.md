## How to use this register

Every `none` and `config` row is repeated below, grouped by the file it comes from. The three kinds of
answer mean different things:

- **`none` — no Payroc equivalent.** The feature has to be redesigned, or the question escalated.
  Read the row before you tell a developer the capability is lost: the row names an alternative or an
  escalation route, and its `C` badge says how well the absence is established.
- **`config` — the capability survives, but it is no longer something your code calls.** Payroc
  configures it. The
  action is a conversation with your Payroc implementation contact, not a rebuild. Telling a developer
  a `config` row is a `none` row tells them they have lost something they have not.
- **`OUT` — the unit was never something a merchant's code called.** It is a staff, admin, test,
  internal or human-UI surface, or a page Payroc hosts. That is different from "no equivalent": there
  is nothing in your integration to port. The OUT rows are in the section below.

Rows are repeated from their own mapping file, hedges and confidence badges included, not summarised.
Do not read a row's presence here as itself a confidence signal: a `none` row can be `verified` or
`unverified`, and the badge on the row is the only guide. Where this register and a domain file
disagree, the domain file wins.

## Cross-cutting facts

- An OUT row means you cannot call the unit as an integration (an internal tool, a screen a person
  uses, a Payroc-hosted page). That is not "no equivalent": the `none` and `config` rows are in the
  copies section.
- The CGIs without a login-session gate that are listed in one OUT row below are staff, admin, test,
  partner or human-UI tools; none is an integration surface. A CGI that a merchant's code,
  or a page a merchant serves to buyers, could send a request to is not in the OUT rows; it has a row
  in [map-direct-cgis.md](map-direct-cgis.md), even if that row says `none`.
- Pages that stop working at the sunset but carry no merchant code (the Payroc-hosted group below) are
  not an integration change. If your buyers use them, raise it with your Payroc implementation contact.
